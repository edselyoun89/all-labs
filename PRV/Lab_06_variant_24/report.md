# Лабораторная работа №6

## Титульный лист

**Дисциплина:** Параллельное программирование  
**Тема:** Документы и приложения общего доступа  
**Работа:** Совместный документ в реальном времени

## Задание

Создать приложение для общего доступа, обеспечивающее параллельную работу нескольких пользователей в реальном времени, редактирование документа, права на редактирование, добавление комментариев или только просмотр, а также просмотр, добавление и изменение данных.

## Введение

Совместные документы позволяют нескольким пользователям работать с одним информационным объектом без ручной пересылки файлов. Основные задачи системы — синхронизация состояния, контроль прав, обнаружение конфликтов и доставка изменений подключённым клиентам.

## Архитектура системы

Использована клиент-серверная архитектура. Сервер является единственным владельцем актуального состояния документа и ACL. Клиенты подключаются по TCP и получают события через JSON Lines.

Выбор архитектуры упрощает согласование версий, проверку прав и рассылку изменений. Каждый клиент обрабатывается в отдельном daemon-потоке, поэтому несколько пользователей могут одновременно подключаться, редактировать и оставлять комментарии.

### Сервер

[server.py](./server.py) содержит `SharedDocumentServer` и `Session`:

- `document` — текущий текст;
- `version` — монотонный номер редакции;
- `comments` — список комментариев;
- `roles` — ACL пользователей;
- `sessions` — активные сокеты.

Состояние защищено `RLock`. Для каждого соединения используется отдельный `Lock` отправки, чтобы события не смешивались в одном TCP-потоке.

### Клиент

[client.py](./client.py) содержит `DocumentClient` и `DocumentWindow`. Клиент имеет отдельный поток получения сообщений и передаёт события в GUI-поток Tkinter через `root.after()`.

Интерфейс включает редактор, кнопку сохранения, номер версии, список пользователей и ролей, панель комментариев, поле номера строки и статус соединения.

### Роли

| Роль | Просмотр | Редактирование | Комментарии | Управление ролями |
|---|:---:|:---:|:---:|:---:|
| admin | да | да | да | да |
| editor | да | да | да | нет |
| commenter | да | нет | да | нет |
| viewer | да | нет | нет | нет |

Первый подключившийся пользователь получает роль `admin`. Сервер проверяет права независимо от GUI.

## Коммуникации и протокол

Используется двунаправленная асинхронная TCP-коммуникация. Каждое сообщение — UTF-8 JSON-объект, завершённый `\n`.

```text
hello     {"type":"hello", "username":"Admin"}
edit      {"type":"edit", "content":"...", "base_version":0}
comment   {"type":"comment", "line":2, "text":"Проверить"}
set_role  {"type":"set_role", "username":"Editor", "role":"editor"}
state     {"type":"state"}
```

## Синхронизация и конфликты

Клиент отправляет `base_version`. Сервер принимает редакцию только при совпадении с текущей версией. После успешного изменения сервер увеличивает `version` и рассылает событие `document`. При устаревшей версии клиент получает `conflict` с актуальным состоянием и не перезаписывает чужую редакцию.

Такой optimistic-locking предотвращает потерю изменений при параллельном редактировании. Все операции изменения документа и ACL выполняются внутри серверной блокировки.

## Реализация и проверка

Автоматический [integration_test.py](./integration_test.py) запускает сервер на свободном TCP-порту и создаёт пользователей Admin, Editor и Viewer. Проверяются назначение ролей, успешное редактирование Editor, запрет редактирования Viewer, добавление комментария и обнаружение устаревшей версии.

Результат проверки:

```text
integration_test: OK
tkinter: OK
```

Все Python-файлы успешно прошли `py_compile`.

## Анализ

В сравнении с [клиентом пятой лабораторной](../Lab_05_variant_24/client.py) текущая работа добавляет серверное состояние документа, ACL, версионирование и комментарии. В пятой работе сервер маршрутизировал чат и координаты, а здесь выполняет роль диспетчера согласованных редакций.

В отличие от [MPI-обмена в четвёртой лабораторной](../Lab_04_variant_24/report.md), здесь коммуникация постоянная и событийная: соединение клиента остаётся открытым, а сервер отправляет обновления сразу после изменения.
