3. КАК ОБЪЯСНИТЬ КЛАССЫ И СИНХРОНИЗАЦИЮ

Task хранит имя, delay, функцию, время планирования, время выполнения,
cancelled, объект Timer, Event done и Lock.
Scheduler.schedule создаёт Timer, запускающий обёртку функции после delay.
Scheduler.run ожидает done каждой задачи. cancel помечает задачу отменённой,
вызывает Timer.cancel и устанавливает done, чтобы ожидание не зависло.
RLock защищает коллекцию планировщика; Lock — состояние отдельной задачи.
LoadWorker — наследник Thread; выполняет короткие CPU-циклы до stop_event.

Timer является потоком и не гарантирует жёсткого запуска ровно через delay.
На время влияют планировщик ОС, GIL и текущая загрузка.
Event позволяет сигнализировать завершение без активного опроса.
Блокировку используют через with, чтобы она освобождалась при исключениях.

4. ЧТО ИМЕННО ИЗМЕРЕНО

Абсолютная ошибка старта = |(executed_at-scheduled_at)-delay|.
Сохраняются среднее и максимум по выполненным задачам; замеры perf_counter.
По три повтора для load_threads=0,2,4,8.
В сохранённом summary средняя ошибка увеличивается примерно
с 0.000323 с без нагрузки до 0.096862 с при восьми фоновых потоках.
Это прежние сохранённые измерения; повторная серия может отличаться.

5. ОГРАНИЧЕНИЯ ЭТОЙ ВЕРСИИ

time_seq=55 с рассчитано как сумма задержек, включая отменённую задачу,
а не измерено последовательным запуском. speedup на этой базе условный.
efficiency делится на число фоновых потоков, поэтому не описывает
эффективность количества Timer. На защите опираться на ошибки старта.

Timer.cancel помогает только до начала callback. В коде есть окно между
проверкой cancelled и началом функции, а executed_at записывается после
функции. Из-за этого cancel может сообщить успех для уже работающей задачи.
Это замечание по коду, отдельный воспроизводимый тест гонки не выполнялся.
Представлять реализацию как гарантию строгой отмены работающей функции нельзя.

6. ВЕРОЯТНЫЕ ВОПРОСЫ И ВЫВОД

Timer или sleep? sleep блокирует текущий поток, Timer запускает callback
из отдельного потока; в этой программе задачи ожидают параллельно.
Зачем монотонный счётчик времени? Измерения не зависят от перевода часов.
Как улучшить точность? Уменьшить конкуренцию и накладные расходы;
обычные Python-потоки всё равно не дают гарантий реального времени.
Чем Event отличается от Lock? Event сообщает состояние/сигнал,
Lock обеспечивает взаимоисключение при доступе к общим данным.

«Timer подходит для учебного отложенного запуска. Под нагрузкой ошибка
старта растёт. В этой версии есть ограничения отмены и метрик ускорения.
Для сдачи варианта 22 используется отдельная приоритетная очередь».
