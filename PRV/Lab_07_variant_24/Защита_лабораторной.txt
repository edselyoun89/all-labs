ЛАБОРАТОРНАЯ №7 В ПАПКЕ ПРОЕКТА. ПАРСИНГ САЙТОВ

В исходной методичке эта тема названа работой №5 и ссылается на общий
документ работы №4. В проекте общий документ находится в ../Lab_06_variant_24.
Отдельной таблицы вариантов в методичке парсинга нет.

1. ЧТО СКАЗАТЬ

«Программа загружает HTML, извлекает заголовки, абзацы и ссылки,
фильтрует их по параметрам и сохраняет JSON, CSV и HTML.
Дополнительно результат передаётся в общий документ из предыдущей работы,
где его можно редактировать. Недоступность сайта обрабатывается сообщением».

2. ВОСПРОИЗВОДИМЫЙ ПОКАЗ БЕЗ ВНЕШНЕГО САЙТА

Команды из папки этой работы, достаточно стандартного Python.
В первом терминале запустить локальный сайт из входящего в папку demo.html:
python -m http.server 8000 --bind 127.0.0.1

Во втором терминале:
python main.py http://127.0.0.1:8000/demo.html --tag all --limit 20 --output-dir results/defense
python main.py http://127.0.0.1:8000/demo.html --keyword MPI --tag paragraphs --output-dir results/defense_filtered

Открыть сохранённые parsed_data.json, .csv и .html и показать разницу выборок.
Проверка ошибки (сервер по этому порту должен отсутствовать):
python main.py http://127.0.0.1:1/unavailable --output-dir results/defense_error
Показать понятное сообщение «Не удалось обработать сайт ...» и ненулевой код.

Автоматический сценарий:
python integration_test.py
Он поднимает собственный локальный HTTP-сайт и сервер общего документа.
Существующий тест также обновляет демонстрационные results/parsed_data.*.

3. ПУБЛИКАЦИЯ И РЕДАКТИРОВАНИЕ В ОБЩЕМ ДОКУМЕНТЕ

В третьем терминале запустить НОВЫЙ сервер общего документа:
python ../Lab_06_variant_24/main.py server --host 127.0.0.1 --port 12346

До подключения других клиентов опубликовать:
python main.py http://127.0.0.1:8000/demo.html --shared-host 127.0.0.1 --shared-port 12346 --username Parser --output-dir results/defense

Parser должен быть первым пользователем этого свежего сервера, тогда он
получит admin и сможет записать текст. На уже занятом сервере ему требуется
назначить editor/admin через существующего администратора.

После завершения команды открыть GUI под тем же именем:
python ../Lab_06_variant_24/main.py client --username Parser
Роль сохраняется в памяти работающего сервера; показать опубликованный текст,
изменить его и нажать «Сохранить изменения». Сервисы остановить Ctrl+C.
Публикация заменяет ВЕСЬ общий документ, а не дописывает отдельную секцию.

4. КАК ОБЪЯСНИТЬ КОД И ПАРАМЕТРЫ

main.py — параметры URL, keyword, tag, limit, output-dir, shared-host и username.
fetch_html в parser.py проверяет схему http/https/file, загружает байты,
определяет кодировку и возвращает HTML с фактическим URL.
SiteParser наследует HTMLParser и обрабатывает открытие, закрытие тегов и текст.
Извлекаются title, заголовки h1..h4, абзацы p, ссылки a с href и текстом.
parse_site применяет регистронезависимый фильтр keyword, выбирает категорию
all/headings/paragraphs/links и ограничивает каждую выбранную коллекцию limit.
save_results формирует JSON для структуры, CSV для таблицы и HTML для просмотра.
HTML-текст экранируется через html.escape.

publish_to_shared_document превращает данные в Markdown, подключается по TCP,
делает hello, получает роль и версию, проверяет право editor/admin,
посылает edit с base_version и ждёт подтверждения document.
Это согласование с тем же протоколом общего документа, отдельная БД не нужна.
parse_with_error_logging превращает сетевые/параметрические ошибки
в понятное сообщение для пользователя; main завершает команду кодом 1.

5. ЧТО ПРОВЕРЕНО И ИЗВЕСТНЫЕ ОГРАНИЧЕНИЯ

Интеграционная проверка 08.11.2026 прошла: локальный HTTP, фильтр,
три формата, публикация в общий документ и недоступный URL.
Существующий HTMLParser рассчитан на простые блоки. Подтверждённый пример:
<p>Hello <b>nested</b> world</p> возвращает только «world», потому что
общий текстовый буфер сбрасывается при закрытии вложенного тега.
Не заявлять полноценную поддержку произвольной разметки сложных сайтов.

total_items считается до limit и может превышать фактически сохранённое число.
Относительный href не преобразуется в абсолютный URL, поэтому ссылка
в локальном HTML может вести не туда. JavaScript не исполняется:
динамически подгружаемый браузером контент не извлекается.
Публикация требует работающего сервера и подходящей роли пользователя.

6. ВЕРОЯТНЫЕ ВОПРОСЫ И ВЫВОД

Чем парсинг отличается от загрузки? Загрузка получает HTML, парсинг
выделяет структуру и нужные элементы, после чего применяется фильтрация.
Зачем три формата? JSON удобен программе, CSV — таблицам, HTML — человеку.
Что означает limit? В этой реализации предел для каждой коллекции,
а не единый суммарный предел для всех категорий.
Что происходит при конфликте документа? Сервер отклоняет устаревшую версию;
клиент публикации сообщает ошибку, автоматического слияния нет.
Почему локальный сайт полезен для защиты? Его содержимое воспроизводимо,
а показ не зависит от интернета и изменения внешней страницы.

публикации в редактируемый общий документ. Основной сценарий проверен,
сложные вложенные теги имеют известное ограничение».
