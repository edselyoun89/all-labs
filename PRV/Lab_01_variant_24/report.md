# Лабораторная работа №1

## Тема

Python + MPI + OpenMP.

## Вариант 24

Вычисление определителя матрицы методом Гаусса с использованием MPI и OpenMP.

## Цель работы

Реализовать параллельный алгоритм вычисления определителя квадратной матрицы, распределив строки между MPI-процессами и распараллелив локальное исключение внутри каждого процесса. Исследовать ускорение, эффективность и масштабируемость.

## Постановка задачи

Для основной серии экспериментов используется `N = 1000` и `p = 1, 2, 4, 8`. Для каждого запуска выполняются три повтора. Время ввода-вывода не включается в замеры. Перед каждым замером выполняется `MPI.Barrier()`.

Требуется вычислить:

`S(p) = T1 / Tp`,

`E(p) = S(p) / p`,

`B(p) = (1/S(p) - 1/p) / (1 - 1/p)`.

Для масштабируемости проверяется условие `E(p) >= 0.5` при `p = 2, 4, 8`.

## Теоретические сведения

Метод Гаусса приводит матрицу к верхнетреугольному виду. Определитель равен произведению диагональных элементов с учётом изменения знака при перестановке строк. Для устойчивого выбора ведущего элемента используется частичный pivoting: на каждом шаге выбирается строка с максимальным по модулю элементом в текущем столбце.

MPI распределяет непрерывные блоки строк. На шаге `k` процессы находят локального кандидата, глобальный pivot выбирается через `allgather`, при необходимости две строки обмениваются через `Sendrecv`, затем pivot-строка рассылается через `Bcast`.

Внутри каждого процесса обновление строк выполняется функцией `eliminate_rows`, объявленной с `@njit(parallel=True)`; цикл по строкам использует `prange`.

Так как для `N = 1000` величина determinant порядка `1000^1000` не представима в `float64`, программа сравнивает знак и `log10(|det A|)`. Это не теряет информацию о результате и предотвращает переполнение.

## Структура программы

- `main.py` — последовательный и MPI+Numba алгоритмы, проверка и замеры.
- `run_experiments.py` — запуск основной серии и масштабируемости.
- `plot_graphs.py` — графики `S(p)`, `E(p)` и `B(p)`.
- `results.csv` — основная серия для `N=1000`.
- `scalability.csv` — фактические точки масштабируемости.

## Экспериментальные результаты

Все запуски завершились с `correct=True`.

| p | T1, с | Tp, с | S(p) | E(p) | B(p) |
|---:|---:|---:|---:|---:|---:|
| 1 | 1.250653 | 0.200761 | 6.2296 | 6.2296 | 0 |
| 2 | 1.267893 | 0.227515 | 5.5728 | 2.7864 | -0.6411 |
| 4 | 1.387535 | 1.882678 | 0.7370 | 0.1843 | 1.4758 |
| 8 | 1.276403 | 34.990500 | 0.0365 | 0.0046 | 31.1867 |

Отрицательное `B` для `p=2` и значения `B>1` при `p=4,8` являются следствием того, что формула Амдала применяется к измерениям с большими коммуникационными и запусковыми накладными расходами; это оценка модели, а не буквальная доля строк программы.

## Масштабируемость

Проверенные точки:

| N | p | E(p) |
|---:|---:|---:|
| 256 | 2 | 0.0884 |
| 256 | 4 | 0.0182 |
| 256 | 8 | 0.0003 |
| 512 | 4 | 0.0197 |
| 512 | 8 | 0.0014 |

В проверенном диапазоне `N <= 512` условие `E >= 0.5` выполнено не было для `p=2,4,8`; `N_min` не найден. Для `N=1000` эффективность также ниже 0.5 для `p=4` и `p=8`. Причина — последовательные обмены pivot-строк на каждом из `N` шагов и высокая стоимость запуска процессов на одной Windows-машине.

## Анализ

При `p=2` на `N=1000` вычисления показывают ускорение относительно последовательного baseline, но эффективность в формальном виде выше единицы, поскольку baseline и параллельная реализация используют разные вычислительные ядра, а локальное исключение прогревается через Numba. Это ограничение интерпретации замеров, а не ошибка корректности.

При `p=4` и `p=8` коммуникации MPI становятся доминирующими: каждый шаг требует глобального выбора pivot, возможного обмена строк и рассылки pivot-строки. Поэтому добавление процессов увеличивает `Tp` быстрее, чем сокращает локальную арифметику.

## Вывод

Разработана программа вычисления определителя методом Гаусса с частичным выбором главного элемента. Реализованы MPI-распределение строк, `Sendrecv`, `Bcast`, проверка результата и OpenMP-подобное распараллеливание через Numba `prange`. Для основной серии все результаты совпали с последовательным вычислением в устойчивом представлении знака и логарифма модуля. На данном компьютере оптимальным из проверенных режимов оказался запуск с небольшим числом MPI-процессов; для `p=4` и `p=8` эффективность ниже требуемого порога 0.5.
