ЛАБОРАТОРНАЯ №5. ВАРИАНТ 24. ГЕОЛОКАЦИОННЫЙ ЧАТ

1. ЧТО СКАЗАТЬ В НАЧАЛЕ

«Я разработал клиент-серверный чат на TCP. Сервер обслуживает клиентов
в отдельных потоках, хранит координаты пользователей, рассылает сообщения
и ищет ближайших участников. Клиент на Tkinter показывает сообщения,
пользователей, координаты и схему карты. Поиск адреса использует внешний
сервис, а географическая карта открывается в браузере».
Здесь вариант 24; вариант 22 по методичке — чат с аналитикой.

2. ДЕМОНСТРАЦИЯ В ТРЁХ ТЕРМИНАЛАХ

Команды выполнять из этой папки. Нужен Python с Tkinter.
Сервер:
python main.py server --host 127.0.0.1 --port 12345
Клиент 1:
python main.py client --username Alice
Клиент 2:
python main.py client --username Bob

1) Показать двух пользователей и статус соединения.
2) Отправить Alice сообщение и увидеть его у Bob.
3) У Alice задать широту 55.7558, долготу 37.6173, метку «Москва».
4) У Bob задать 55.7600, 37.6200, метку «Рядом»; отправить координаты.
5) Показать маркеры на схеме и поиск ближайших в радиусе 5 км.
6) Объяснить отдельную кнопку открытия OpenStreetMap.
7) Поиск адреса показывать при работающем интернете; он зависит от Nominatim.
8) Закрыть клиентов, сервер остановить Ctrl+C.

Автоматическая проверка без GUI:
python integration_test.py
Она использует отдельный свободный порт и не требует поиска адреса в сети.

3. АРХИТЕКТУРА И ФАЙЛЫ

main.py выбирает режим server/client и разбирает параметры.
server.py: ChatServer, ClientSession, send_json, haversine_km.
client.py: ChatClient для соединения и ChatWindow для интерфейса.
Сервер — центральный источник списка клиентов и координат. У него accept-loop,
а каждому соединению соответствует отдельный поток handle_client.
Словарь пользователей защищён RLock. Отдельный Lock отправки каждого
соединения не позволяет двум рассылкам смешать байты сообщений.

Сервер bind/listen/accept принимает подключение. Клиент connect создаёт
TCP-соединение; sendall передаёт данные, recv читает очередной фрагмент.
TCP — поток байтов: один recv не обязан соответствовать одному сообщению.
Протокол JSON Lines отделяет события символом новой строки.
События: hello, chat, location, users, nearby; ответы содержат type.
Клиент имеет поток чтения, а обновления интерфейса передаются в GUI
через root.after, чтобы обработка сообщений не блокировала основной цикл.

4. ГЕОЛОКАЦИЯ

Сервер проверяет диапазоны широты [-90,90] и долготы [-180,180].
haversine_km вычисляет расстояние по формуле гаверсинуса на сфере:
d=2R*asin(sqrt(sin²(Δφ/2)+cos φ1*cos φ2*sin²(Δλ/2))).
R≈6371 км; углы переводятся в радианы.
nearby фильтрует пользователей по радиусу и сортирует по расстоянию.
Сервер может включить в выдачу и самого пользователя, если он в радиусе.

Координаты вводятся вручную или подставляются из поиска адреса;
автоматическое получение GPS этой версией не реализовано.
Встроенная карта — координатная схема, а не картографические тайлы.

5. ЧТО ПРОВЕРЕНО И ЧЕГО НЕ ПРЕУВЕЛИЧИВАТЬ

Проверка 08.11.2026: два клиента, регистрация, chat, location и nearby — OK.
Содержимое сообщений и набор пользователей в радиусе проверяются тестом.
GUI и внешний сервис адресов не были проверены этим автоматическим тестом.
Показать main.py, блокировки сервера, протокол, функцию расстояния и report.md.

Состояние хранится в оперативной памяти, история не сохраняется в БД.
Есть проверка уникального имени, но нет парольной аутентификации или TLS.
В текущем коде decode UTF-8 делается по каждому recv: при разрыве символа
между TCP-фрагментами возможна ошибка. Уже накопленная после hello строка
может ждать следующего recv. Это известные ограничения учебного протокола.

6. ВЕРОЯТНЫЕ ВОПРОСЫ И ВЫВОД

Почему TCP? Нужен упорядоченный надёжный обмен событиями чата.
Зачем потоки? Один ожидающий клиент не должен блокировать остальные.
Зачем Lock при sendall? Несколько серверных потоков могут отправлять
в один и тот же сокет; блокировка сохраняет целостность JSON-строки.
Почему RLock? Некоторые операции состояния вызывают другие защищённые
операции в том же потоке; рекурсивная блокировка допускает повторный вход.
Как работать на разных компьютерах? Сервер слушает доступный адрес,
клиенты используют его IP вместо localhost; нужен доступ к порту.
Что будет без интернета? Локальный чат и ручные координаты работают,
адресный поиск и внешняя веб-карта могут быть недоступны.

«Чат демонстрирует многопоточную обработку TCP-клиентов, передачу координат
и поиск ближайших. Основные сетевые сценарии подтверждены тестом».
